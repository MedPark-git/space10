# 재고현황 및 재고분석

MedPark 사내용 재고관리 웹 애플리케이션입니다. Flask/Gunicorn/PostgreSQL/SQLAlchemy로 구성되며 운영 환경에서 SQLite로 대체하지 않습니다.

## 주요 메뉴

- 대시보드: 총 품목, 재고금액, 안전재고 미달, 최근 입출고
- 품목 관리: 품목 등록·수정, 현재고·안전재고·단가 관리
- 입출고 관리: 입고·출고 등록 및 이력 검색
- 재고 분석: 재고금액 상위 품목, 안전재고 미달, 장기 미동 품목
- 사용자 관리, 내 정보, 비밀번호 변경, 감사 로그

## 운영 설정

AI SPACE가 제공하는 `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`가 모두 필요합니다. `SECRET_KEY`가 없다면 `/app/user_data/private/session.json`에 무작위 세션키를 최초 한 번 생성하고 모든 작업자가 공유합니다. 최초 관리자용 환경변수가 없다면 임시 관리자 `admin`과 무작위 비밀번호를 생성합니다. 초기 비밀번호는 서버의 보호된 `/app/user_data/private/bootstrap-admin.json`에만 기록하며 최초 비밀번호 변경 시 삭제됩니다. 비밀번호 평문은 공개 웹 경로에 노출하지 않습니다. 초기 관리자 접속정보는 소유자에게 별도 인계했습니다. 인계용 공개키 설정과 임시 웹 전달 경로(`/setup/bootstrap-envelope`)는 인계 후 제거했습니다. 암호화 유틸리티는 서버 내부 운영 도구로만 사용할 수 있습니다. 개인키와 평문 접속정보는 저장소에 넣지 않습니다. 실제 비밀번호나 DB 접속정보는 저장소에 기록하지 않습니다.

시작 명령:

```text
gunicorn --workers 2 --threads 4 --timeout 120 --bind 0.0.0.0:${PORT:-8000} app:app
```

서버 시작 시 PostgreSQL advisory lock으로 초기 스키마 처리를 직렬화합니다. 사용자 테이블이 비어 있을 때만 부트스트랩 관리자를 생성합니다.

## 유효기간 초안 (space10)

- `/expiry/special-rules`: 계열 공통 기간 추가·수정·사용 중지, 변경 사유/최신 재고 영향 미리보기/확정/이력. admin/editor 수정, viewer 조회. 적용 확정 전 기준정보와 최신 재고 변경을 재검증
- 42AP·44AP·48AP·49AP는 배포 기본 규칙으로 끝자리와 무관하게 생산일 + 1,095일 − 1일 적용. 화면에서 수정·중지한 값은 DB에 저장되어 기본값보다 우선
- 계산 우선순위: 특정 LOT 확정 날짜 → 활성 계열 공통 기간 → 일반 규칙. 계열 공통 기간은 생산일 LOT 전용이며 MTS 날짜에 기간을 더하지 않음
- 확정된 재고 원본은 유지하지만 계산 결과는 현재 규칙으로 다시 산출. 규칙 변경은 과거 재고에도 반영되며 영향 미리보기는 최신 재고 기준
- `/expiry/`: 날짜별 ERP 재고 조회, 창고·공장·상태·품번·LOT 검색, CSV 출력
- ERP 재고·품번 마스터·유효기간 규칙·MTS 사용기한·LOT 예외를 열 제목 포함 TSV로 붙여넣기
- 미리보기 후 확정. 재고는 스냅샷으로 보존하고 기준정보는 KEY별 추가·수정하며 누락된 기존 KEY는 유지
- 1·2공장은 ICUBE 품번 앞 4자리와 뒤 2자리로 규칙을 찾고 생산일 + 유효일수 − 1일 계산
- 기존 XBP LOT만 4~9자리 날짜 사용. 그 외 생산일 LOT는 3~8자리 날짜 사용
- ERP 재고는 계정구분 열 필수. 제품만 현황·집계·CSV에 반영하며 반제품/다른 계정/미분류는 제외. 원본은 검증·이력용으로 보관. 계정구분 없는 기존 스냅샷은 재등록 안내
- 3공장은 앞 4자리+끝 2자리 개별 규칙 우선, 등록된 공통(*) 규칙은 보완용. 같은 3공장의 개별·공통 규칙은 공존 가능. MTS 제품구분+앞 8자리 LOT로 연결하며 MTS 사용기한 사용
- HAHA GEN ↔ S GEN 동일 제품명 인식, INJECT형은 별도. 일반 별칭은 MTS 제품구분에서 |로 구분. 원래 품명·전체 품번은 유지
- 41 계열의 품명 또는 규칙에 TIBIALIS가 있으면 Anterior/Posterior 공통 MTS 매칭. 규칙 미등록이어도 명시된 41+TIBIALIS는 인식하되 날짜 충돌 시 확인 필요
- 같은 제품구분·LOT에 사용기한이 충돌하거나 기준정보가 없으면 날짜를 생성하지 않고 확인사항 표시
- 기본 화면 알림은 잔여 90·180·365일 미만. 일수는 편집자가 변경 가능. 이메일·메신저 발송 없음
- admin/editor 등록·수정, viewer 조회. CSRF, 등록자 제한, 중복 확정 방지, 기준정보 변경 감지, 감사 기록
- 기존 품목·입출고 테이블에는 쓰지 않음. `expiry_references`, `expiry_imports`만 추가

로컬 확인: `python3 -m pytest -q`. 워크플로 테스트는 격리된 메모리 데이터베이스를 사용하므로 PostgreSQL advisory lock의 실제 동작은 운영 연결 후 별도 확인해야 합니다. 운영 저장소는 PostgreSQL만 사용합니다.

실제 재고·품번 마스터·MTS 파일은 공개 GitHub에 커밋하지 않습니다. 사이트 등록 화면으로 입력합니다. 현재 별도 ERP API 연동은 없습니다.
